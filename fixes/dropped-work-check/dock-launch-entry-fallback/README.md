# dock-launch-entry-fallback (tModLoader thread, Nov 25 2026)
Ours. Swift only (ContentView.swift startDock, SteamGames.swift SteamDirectStart). Base 0.2.99/0.2.100 source (commit ca1408d). Patch: `patch -p1` from the source root (paths app/Madeira/...).
**Bug (PROVEN):** tModLoader (app 1281930) through Madeira Dock fails "Steam could not find the game's executable", launch-client-error=28. Madeira log (iPad 0.2.99): "[start-scan] ... entry: none", "[madeira-dock] launch option 0 (none chosen: the default)". Steam content_log: "Failed running app 1281930 (missing executable ...\tModLoader\tModLoader.exe)". Steam's appinfo (from the iPad thread): launch/0 = tModLoader.exe with BetaKey 1.3-legacy; launch/3 = start-tModLoader.bat, windows, no BetaKey. SteamDirectStart.choose only takes .exe entries, so it found none, and Dock fell back to entry 0, the beta-only one.
**Fix:** when choose finds nothing, ask Steam for the best Windows entry outside beta branches (same candidate rules as choose, but any program type), here index 3. Logs "[dock-launch-fallback] ...".
**Off switch:** `env.MADEIRA_DOCK_LAUNCH_FALLBACK = 0` (global madeira.cfg; on by default). Off = old default 0.
Affects only Dock starts where choose returns nil (no .exe entry on disk) and a non-beta Windows entry exists. Games with a normal .exe entry are unchanged. Golden games: any Dock game whose launch entries are not an .exe on disk; check the log line shows only for them.
NOT compiled for iOS, not device-tested. Does not itself make tModLoader run: start-tModLoader.bat then needs its own steps (dotnet install script, arguments).
