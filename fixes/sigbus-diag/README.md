# sigbus-diag (Requiem thread, Nov 25 2026) — LOG ONLY, no behaviour change. For 0.2.102.

**Why:** Requiem (re9, iPhone18,1; Sentry GET-HELP-LOGS-2QA events 9d9f4a0b / 1652d8d0 / fdba9eaf) dies ~40 s in after `E F8 Unhandled JIT SIGBUS: PC: 0x13c72fcc0 Instruction: 0xad3948c0` (= STP q0,q18,[x6,#-224], a 32-byte vector store; decode checked on host). FEXCore's HandleUnalignedAccess declines it and logs only PC + instruction, so we cannot tell alignment fault vs protection fault vs a store that crosses into another page. The same run logs `[field] ml964 *** TRUNCATION HAPPENED HERE *** addr=0x70642ef1b6` (the unsolved RDR2 pointer-truncation hunt, ml962-964 in signal_arm64_ios.c) right before. Pool size is not the cause (peak 333/418 MB with pool-low).

**Two files (both log only):**
1. `0025-fexcore-sigbus-diag.patch` — FEX patch (goes in build/fex-patches/, applies with git apply -p1 from FEX/, ARM64EC module only): when HandleUnalignedAccess declines, logs `[sigbus-diag] rev=sigbus-diag-1 #N declined pc= insn= prev= next= kind= Rn= base= ea= size= align16= crosses64= crosses16K= page1[...] page2[...]` (effective address from the context registers for LDP/STP pairs; Windows' State/Protect/Type of the page(s)). First 32 per path, then every 1000th; the line says `sigbus` (the SIGBUS path) or `smc` (the self-modifying-code path, where declines are routine), each with its own counter. Init line: `FEX: sigbus-diag rev=sigbus-diag-1 madeira on`.
2. `ntdll-sigbus-diag.patch` — build/ntdll-unix/signal_arm64_ios.c (apply with patch -p1 from the Madeira dir): in the Q-pair store emulator, when the store is NOT emulated, logs `[sigbus-diag] rev=sigbus-diag-1 #N q-pair store NOT emulated insn= pc= mode= Rn= base= off= effective= fault= in_range= alias_write=refused|not tried alias_fault= honor_guest_prot= fault_mod16= crosses16K=` (first 16).

**fix-markers.sh marker:** `[sigbus-diag] rev=sigbus-diag-1` (present in both).
**Off switch (no rebuild):** `env.MADEIRA_SIGBUS_DIAG = 0` in the game's config (both logs off; FEX init line says "off").
**Host checks done (re-run after the review fix):** both patches `patch --dry-run` clean on 0.2.101 source; the C++ function compiles with a compile-time-checked std::format and mocked types (output line seen), and the C block extracted from the patched file compiles with -Wall -Wextra and runs; 0xad3948c0 decodes to pair=1 Q store Rt=q0 Rt2=q18 Rn=x6 imm=-224 size 32. NOT compiled in the real FEX/Wine build (no iOS toolchain here), NOT device-tested.
**Not in this patch:** any fix. WOW64 module (32-bit) untouched. The FEXCore implementation of HandleUnalignedAccess (where "Unhandled JIT SIGBUS" is printed) is not in the shared source copy, so the FEX-side log is in Module.cpp's wrapper.
**What to look for after 0.2.102:** a Requiem Get Help log with `[sigbus-diag]` lines: in_range=0 (registers don't explain the fault), alias_write=refused (alias write failed), crosses16K=1 (store spans two host pages), page2 state/protect (second page unmapped or read-only).
