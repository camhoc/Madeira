# steam-sdl3-x64 (Nov 28) — a 64-bit SDL3.dll for Dock's Steam client

Online: Vuqar05/Madeira (GPL-3.0-or-later with the Converter Exception, a Madeira fork; not BCD), commit bfb0e07 "Steam Input: a 64-bit SDL3.dll for Dock's Steam client" (also ec95dfd55, 6f9ecb4a1) and its docs/STEAM_INPUT.md. Credit: Vugar (Vuqar05). Upstream SDL is zlib.

Cause (source-backed, matches our logs): steamclient64.dll reads pads through SDL3.dll. The pinned Steam client ships only a 32-bit SDL3.dll (for steam.exe). The 64-bit client in dockhost.exe loads Steam\SDL3.dll first, gets STATUS_INVALID_IMAGE_FORMAT (c000007b), then the search by name finds nothing (c0000135). Our logs show exactly that pair (0.2.101 Besiege/Detroit) and Steam's controller.txt says "CHIDDeviceListSDL(): Couldn't load SDL3.dll, not enumerating devices" (0.2.180 hid-pad-check.txt). The fix is upstream SDL, unmodified, at the commit Valve's copy reports (b1362f8a4, 3.4.0-98), built for x86-64 and bundled in app/Madeira/arm64ec-windows/ so the DLL farm links it into C:\windows\system32 next to dockhost.exe.

Files: build.sh (copied from the fork; builds with llvm-mingw, LLVM_MINGW=<dir> overrides the toolchain; stages SDL3.dll + sdl3-notices.txt in app/Madeira/arm64ec-windows/), gitignore-hunk.txt (the two outputs are build outputs, not committed), NOTICES-row.md (row for THIRD-PARTY-NOTICES.md).
Build check done here (Linux, llvm-mingw 20260421): SDL checked out at b1362f8a4, builds clean, stripped DLL 2,993,152 bytes, PE machine 0x8664 (x86-64), sha256 f9830990b3bf7d3a633aa6f3561ca26a5dca96b33136e2c6488f5112d565dbbb. The macOS build on the laptop may differ in bytes.
Off switch: nothing runs unless Steam Input is on; remove the DLL (or skip build.sh) to go back. The DLL alone only changes what Steam does with a HID pad (env.MADEIRA_PAD_MODE = hid): it lets the Steam client list it.
NOT device-tested. Also needed for Steam Input to work end to end (separate pieces, not in this folder): a USB parent for the virtual DualSense (fork 748f407), XInput forwarding to xinput1_4 (6c40e44), self-process memory writes for Steam's overlay hooks (911938043), SDL gamepad init in Dock (aa5eeb3). Test after this lands: Steam's controller.txt should no longer say "Couldn't load SDL3.dll".
